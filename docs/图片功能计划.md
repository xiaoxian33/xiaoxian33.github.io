# 帖子图片功能 · 计划

> 状态：✅ **已做完（2026-09-17）** —— 见下面「实际做出来的样子」，和当初的计划有两处不同。
>
> 需求：帖子 = 标题 + 正文 + 多张图片（记录每次学习）。**随笔也一样**。前端风格与全站保持一致。

## 实际做出来的样子（和计划的差别）

| 当初的计划 | 实际做的 | 为什么改 |
|---|---|---|
| 新建 `post_image` 表 | 新建一张**通用**的 `image` 表（`owner_type` 区分是帖子还是随笔的图）| 随笔后来也要配图；两张表要写两套一模一样的代码 |
| 接口里的 `images` 是对象数组 | 就是**路径字符串数组** | 发过去和读回来形状一样，前端最好处理（改图 = 整条提交） |
| 单独一个 `DELETE /api/admin/images/{id}` | **不做**了 | 保存时本来就是"整条替换"，在表单里 ✕ 掉一张再保存 = 删掉它，不需要多一个接口 |
| 上传接口返回路径 | 一样（`{ok, path, size}`） | ✔ |

**实测记录**（2026-09-17）：后端 20 项接口测试 + 前端 12 项点击测试全过；
含"没令牌 = 401"、"传 .txt 被拒"、"传 6MB 被拒"、"删除帖子连带清掉图片记录"。

## 一、要不要新建图片表

要。用「一对多」的标准做法：

| 方案 | 结构 | 好处 | 坏处 |
|---|---|---|---|
| A. 新建 `post_image` 表（推荐）| `id / post_id / path / sort_order / created_at` | 一帖多图、能排序、能单删 | 多一张表 |
| B. 在 `post` 表塞一个逗号分隔的路径字段 | `images = "a.jpg,b.jpg"` | 简单 | 不能排序、不能单删、查询麻烦 |

选 A。「一张帖子有多张图」就是典型的**一对多**。

新建表按现有做法走 5 步（见 [代码结构.md](代码结构.md)）：
实体 → 仓库 → 表单 → 读接口 → 写接口。

## 二、图片文件存哪

数据库里只存**路径**，文件本身落在磁盘上：

    数据库：  post_image.path = "uploads/2026/09/abc.jpg"
    磁盘上：  某个目录/uploads/2026/09/abc.jpg

不能放 `assets/img/` —— 那里是 git 仓库里的静态资源；
帖子图是**运行时上传**的，会越来越多，也不该进版本库。

所以还需要一个新能力：**文件上传**
（前端选图 → 发给后端 → 后端存盘 → 返回路径）。
后端还要配置静态资源映射，让上传的图能通过 URL 访问。

## 三、接口要动哪些

### 1. 读接口改形状

| 接口 | 现在 | 改成 |
|---|---|---|
| `GET /api/posts` | 每条帖子不带图 | 每条帖子多一个 `images` 数组 |

注意：这是**接头点变了** —— 前端的 `postFromApi()` 翻译层必须跟着改。

### 2. 新增上传接口

| 方法 | 路径 | 作用 |
|---|---|---|
| `POST` | `/api/admin/uploads` | 上传图片，返回路径 |

### 3. 写接口改形状

| 接口 | 改什么 |
|---|---|
| `POST /api/admin/posts` | 请求体能带图片列表 |
| `PUT /api/admin/posts/{id}` | 同上 |
| `DELETE /api/admin/posts/{id}` | 顺带删掉关联的图片记录 |
| `DELETE /api/admin/images/{id}` | 单独删一张图 |

新增接口只要挂在 `/api/admin/` 下面，**门卫一行都不用改**。

## 四、改动清单

| 层 | 要改什么 |
|---|---|
| 数据库 | 新增 `post_image` 表 |
| 后端实体 | 新增 `PostImage.java`；`Post.java` 加一对多关联 |
| 后端仓库 | 新增 `PostImageRepository.java` |

| 后端接口 | 新增上传接口；`PostController` / `PostAdminController` 改返回体 |

| 前端翻译层 | `postFromApi()` 要处理 `images` |
| 前端渲染层 | `postHTML()` 要渲染图片 |
| 前端管理页 | 选图 / 上传 / 预览 / 删除 |
| 样式 | 图片卡片、画廊、缩略图 |

## 五、makeExcerpt() 要不要留

看列表页怎么设计：

| 列表页设计 | 还需要摘要吗 | `makeExcerpt()` |
|---|---|---|
| 卡片 = 封面图 + 标题 + 日期 + 标签（不放文字）| 不需要 | 可以删掉 |
| 卡片 = 标题 + 一小段文字 + 标签 | 需要 | 留着 |

结论：加工类的翻译不会凭空消失，只会「不需要了」或者「换个地方做」。
（以后若又想要摘要，也可以让后端直接返回 `excerpt` 字段。）

## 六、建议顺序

1. 先做完「真登录」（`POST /api/login` 拿令牌）
2. 再做图片 —— 因为上传接口也要带令牌，先把令牌那条路走通
