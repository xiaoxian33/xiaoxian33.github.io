## 第 1 天 · 2026-09-10

**Q：后端是不是前端和数据库之间的桥梁？**
是。前端只会说 JSON，数据库只懂 SQL，**后端是中间那个既懂两边、又握着钥匙的人**。

**Q：请求 / 响应 / 接口是什么？**
- 请求 = 我发出去的一封信（动词 + 地址 + 内容）
- 响应 = 回信（状态码 200 / 401 / 404…… + 内容）
- 接口 = 约定好的窗口：地址 + 用什么动词 + 会还我什么

**Q：门卫是怎么校验身份和权限的？**
密码只发一次（登录）→ 后端发一张令牌 → 之后每次"写"都带上令牌 → 门卫检查。

**Q：我要看懂所有代码吗？**
不用。记住这几个就够：**实体=表、仓库=取数据、控制器=窗口、门卫=查令牌**；框架内部先当黑盒。

**Q：MySQL 的账号密码，能在另一台电脑上同步用吗？**
不能。每台电脑的 MySQL 各自独立，密码也各自独立。
能搬的只有**数据**：导出 `.sql` → 拷过去 → 导入。（想省事，就把两台电脑的密码设成一样。）

**Q：这些内容现在只是在前端显示吗？以后要放进数据库吗？**
现在都写在 `index.html` 里。
以后放进数据库的，是**我会经常改的东西**：随笔、发帖、简介。技能 / 项目 / 教育经历可以放也可以不放。

## 第 3 天 · 2026-09-12

**Q：门卫是后端做的事吗？**
是，全在后端。前端只负责"把密码发过去、把令牌存起来"。

**Q：前端拿到 token，就等于允许连接数据库了吗？**
不是，这是两件事：
- **连接数据库**：后端启动时就一直连着（和令牌无关）
- **令牌**：只决定"这次操作允不允许做"

一句话：**数据库的门，后端一直开着；令牌管的是"谁有权让后端替他做事"。**

**Q：后端会把前端发来的 JSON 翻译成 SQL 吗？**
会，而且是两段翻译：
`JSON →（Jackson）→ Java 对象 →（Hibernate）→ SQL`

**Q：用了 JPA 就不用 SQL 了吗？**
不是不用，是**不用我亲手写**。JPA 照样生成 SQL 发给 MySQL，只是这句 SQL 由它替我写了。

**Q：接下来是不是就是建各种表，重复"把随笔接进数据库"那件事？**
是。同一套配方换内容：**表的设计图 → 仓库 → 窗口**；写接口挂在 `/api/admin/` 下，自动被门卫保护。

**Q："写接口"是什么意思？**
就是"**拿到令牌之后，真正去改数据库**"的那几个接口：
`POST /api/admin/essays`（新增）· `PUT /api/admin/essays/{id}`（修改）· `DELETE /api/admin/essays/{id}`（删除）

## 第 4 天 · 2026-09-13

**Q：后端这么多表，都已经接好了吗？**
一开始只有 `essay`（随笔）走通了全程。今天补上另外两张：
- `profile` —— 我的资料，**永远只有一行**（名字 / 一句话 / 简介 / 头像和背景图的路径）
- `post` —— 发帖（标题 / 正文 / 标签 / 日期）

还差一张可选的 `owner_token`（把令牌存进数据库，重启后端就不用重新登录）。

**Q：什么叫做水平越权（IDOR）？我们是在哪里处理的？**
IDOR = **同样是普通用户，却动了别人的数据**。
最典型的场景：网址里带一个 id，把它改个数字就看到了别人的私密内容：

```
GET /api/memos?userId=1   →（改成）→   GET /api/memos?userId=2
```

根因只有一句：**后端相信了前端说的"我是谁"**。

处理它的是**上一个项目（Cyber-Tunnel）**，不是这个网站：
- 改前：前端传 `userId`，后端照着查 → 改数字就能越权
- 改后：后端签发令牌 → 从令牌里推出**真实的 userId** → 每次查询都加归属条件（`findByIdAndUserId`）
- 记录在那边仓库的 `docs/AUTH-SECURITY.md`

分清两件事（很容易混）：

| | 管什么 | 在哪 |
|---|---|---|
| 认证 / 授权（门卫） | 你是不是站长、**能不能写** | 这个网站：`/api/admin/**` |
| 归属校验（防 IDOR） | **这条数据是不是你的** | Cyber-Tunnel：`findByIdAndUserId` |

这个网站只有一个作者，所以暂时**不需要**归属校验；以后加了"访客留言"或变成多用户，就必须加。

## 第 5 天 · 2026-09-14

### 今天做了什么

| 页面 | 接的接口 | 新写的代码 |
|---|---|---|
| 关于我 | `GET /api/profile` | `loadProfile()` / `applyProfile()` |
| 随笔 | `GET /api/essays` | `essayHTML()` / `loadEssays()` |
| 发帖 | `GET /api/posts` | `postFromApi()` / `loadPosts()` |

统一做法（渐进增强）：

    页面加载
      ├─ 先用 HTML 里写好的内容显示      ← 后端没开也不会白屏
      └─ 同时去问后端要
           ├─ 拿到了   → 覆盖页面上的内容
           └─ 没拿到   → 什么都不做，继续用旧内容

### 一次请求，数据要变 5 次形态

| 环节 | 形态 | 谁翻译 |
|---|---|---|
| MySQL | 表里的一行，`body` 是纯字符 | — |
| Java 内存 | `Essay` 对象 | Hibernate / JPA（映射）|
| 网络传输 | JSON 文字 | Jackson（序列化）|
| 浏览器 JS | 普通对象 | `res.json()`（反序列化）|
| 屏幕 | HTML 标签 + CSS → 像素 | 我写的 `map` / `join`；浏览器（渲染）|

    表  →  对象  →  JSON  →  JS 对象  →  HTML  →  像素

每一层之间"说法"不同，所以每一步都要翻译。

### 翻译 vs 复用（两个独立的概念）

| | 翻译（适配）| 复用 |
|---|---|---|
| 定义 | 一种形状 → 另一种形状 | 一份数据 → 喂给多个地方 |
| 为什么需要 | 两边的说法不一样 | 多个地方要显示同一样东西 |
| 例子 | `postFromApi()`、日期格式化 | `drawHome` / `drawAll` 共用 `POSTS` |

发帖功能两样都需要：

    后端 JSON
        │  postFromApi()       翻译 1 次
        ▼
    一份数据 POSTS
        ├──► drawHome()       首页「近期发帖」
        └──► drawAll()        「发帖」页

反证：随笔页只有 1 个使用者，也照样需要翻译。
所以翻译不是"页面多"造成的，而是"两边说法不同"造成的。

### 分层

发帖这条链现在是 4 层，每层只干一件事：

    后端 JSON
        │  翻译层   postFromApi()      只管数据长什么样
        ▼
    页面要的数据 { date, title, excerpt, tags }
        │  渲染层   postHTML()         只管数据怎么变成 HTML
        ▼
    HTML 文字
        │  插入层   innerHTML =
        ▼
    屏幕

好处：
1. 改动不扩散：后端改字段名，只改翻译层 1 行
2. 好排查：数据不对查翻译层，样式不对查渲染层
3. 可复用：同一套渲染函数，换个容器就能用在别处

### 为什么一段文字会变成两个段落

数据库里没有"段落"，只有一串字符，中间夹着两个看不见的换行符（`\n`）。

    "…读数据了。\n\n它还顺便…"
                  ↑↑ 两个换行符，看不见，但占位置

两个换行符 = 一个空行（跟记事本里按两次回车一样）。

但 HTML 会把换行吃掉：连续的空白（空格 / 换行 / Tab）都只当作一个空格。

    <p>
      第一行
      第二行
    </p>
    → 渲染成：第一行 第二行

所以在网页上换行 / 分段必须靠标签：

| 标签 | 效果 | 用在哪 |
|---|---|---|
| `<br />` | 换行（同一段之内）| 「关于我」的简介 |
| `<p>` | 分段（新的一段，上下有间距）| 「随笔」的正文 |

完整流程：

    ① 数据库：  "…\n\n…"                     1 条字符串，含 2 个换行符
          │  split(/\n\s*\n/)                剪开
          ▼
    ② 数组：   ["第一段", "第二段"]            2 个元素
          │  map(每块包一层 <p>)              穿衣服
          ▼
    ③ 数组：   ["<p>第一段</p>", "<p>第二段</p>"]
          │  join('')                        粘回去
          ▼
    ④ 字符串： "<p>第一段</p><p>第二段</p>"
          │  innerHTML =
          ▼
    ⑤ 屏幕：   两个有间距的段落

数据库只管存字符，排版是前端用标签做出来的。

### split / map / join

| 工具 | 干什么 | 输入 → 输出 | 例子 |
|---|---|---|---|
| `split` | 按"刀口"剪开 | 字符串 → 数组 | `"A-B".split("-")` → `["A","B"]` |
| `map` | 逐个加工 | 数组 → 新数组 | `[1,2].map(n => n*2)` → `[2,4]` |
| `join` | 粘起来 | 数组 → 字符串 | `["A","B"].join("")` → `"AB"` |

注意：map 里写函数名，不加括号。
`map(essayHTML)` 对，`map(essayHTML())` 错（加了括号就是立刻执行，然后报错）。
因为是把"这台机器"交给 map，不是现在就开机。

为什么最后要 join：innerHTML 只接受一个字符串，不吃数组。

### split 的刀口为什么写 /\n\s*\n/

| 符号 | 意思 | 为什么要 |
|---|---|---|
| `\n` | 一个换行 | 必须有 |
| `\s*` | 零个或多个空白（空格 / Tab）| 防止有人在空行里多敲了空格 |
| `\n` | 又一个换行 | 必须有 |

合起来 = 空行。
只写 `/\n\n/` 切不了 "⏎   ⏎" 这种；`\s*` 是防御性写法。

### 重启电脑后连不上后端

| 东西 | 启动方式 | 重启后 |
|---|---|---|
| MySQL | Windows 服务（开机自启）| 自动起来 |
| 后端 Spring Boot | 手动跑的临时进程 | 没了 |

所以每次重启电脑后，双击 `D:\myworks\start-backend.bat`。
看到 `Started SiteServerApplication` 才算启动成功。窗口不能关。

排查顺序：

    1. 浏览器打开 http://localhost:8080/api/profile
         打不开 → 就是后端没开
    2. 看 start-backend.bat 的窗口有没有报错
    3. 确认看到 Started SiteServerApplication
