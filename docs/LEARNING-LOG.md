## 第 1 天 · 2026-09-10 · 网站上线 + 后端起步

### 做了什么
- 建仓库 `xiaoxian33.github.io`，网站上线到 GitHub Pages
- 页面：关于我 / 教育经历 / 兴趣爱好 / 专业技能 / 做过的项目 / 随笔 / 发帖
- 隐藏入口：同时按 `↑` 和 `←` 打开密码框（**当时是前端版，密码写在前端**）
- 用 Spring Initializr 生成后端骨架，写出第一个接口 `GET /api/hello`

### 重要知识点
**1. 前端要数据，必须"问后端"**
- 前端（浏览器）只会说 JSON / HTTP；数据库只懂 SQL
- **后端是中间那个既懂两边、又握着钥匙的人**
- 所以"发帖 / 改简介"这类事，光有网页文件做不到

**2. 一个请求长什么样**
- 请求 = 动词（`GET` 看 / `POST` 新建 / `PUT` 改 / `DELETE` 删）+ 地址 + 附带信息（Header / Body）
- 响应 = 状态码（`200` 成功 / `401` 没登录 / `403` 没权限 / `404` 找不到 / `500` 后端崩了）+ 内容
- 想亲眼看：**F12 → Network → 刷新**

**3. CORS（跨域）**
- 网页在 `xiaoxian33.github.io`，后端在 `localhost:8080` —— 两个"门牌号"，浏览器默认拦住
- 后端加 `@CrossOrigin` = 发一张"允许访问"的通行证

**4. `localhost` 的意思是"这台电脑自己"**
- 所以别人打开你的网站，永远连不上你电脑上的后端 → 这就是最后要租服务器的原因

## 第 2 天 · 2026-09-11 · 把随笔搬进 MySQL

### 做了什么
- 装好 MySQL（本机 8.0；另一台电脑 8.4），建库 `site_db`
- 后端连上数据库；`essay` 表自动建好；8 篇旧文自动导入
- 做出 `GET /api/essays`，亲眼看到 JPA 生成的真实 SQL

### 重要知识点
**1. 数据库这块只有 4 个角色 + 1 个地址簿**

| 角色 | 文件 | 一句话 |
|---|---|---|
| 📐 表的设计图 | `Essay.java`（实体） | 一个字段 = 表里的一列；启动时自动建表 |
| 🧑‍💼 库管 | `EssayRepository.java` | 提要求（方法名），**一行方法 = 一条查询** |
| 🧑‍🍳 服务员 | `EssayController.java` | 对外窗口 `/api/essays`，把结果端成 JSON |
| 🚚 搬运工 | `DataSeeder.java` | 表为空时把旧文搬进去（只跑一次） |
| 📇 地址簿 | `application.properties` | 仓库在哪、账号；**密码在本地私有文件里** |

**2. 数据到底存在哪**
- 文章**只存在 MySQL** 里；`Essay.java` 里没有文章，只有"表头"
- 图片也不进数据库：文件存磁盘，数据库里只存路径

**3. JPA ≠ 不用 SQL**
- JPA 只是**替你写了** SQL。你看到的真实语句：`select ... from essay order by written_on`
- 想看就把 `spring.jpa.show-sql=true` 打开

**4. 两台电脑的 MySQL 不会自动同步**
- 账号密码各自独立；数据靠"导出 `.sql` → 导入"来搬

## 第 3 天 · 2026-09-12 · 门卫与令牌（今天问得最多）

### 做了什么
- 登录接口：`POST /api/login`（密码 → 令牌）、`POST /api/logout`（令牌作废）
- 门卫：`OwnerAuthInterceptor` + `WebConfig`，只守 `/api/admin/**`
- 验证结果：不带令牌 401 ✅ ｜ 错密码 401 ✅ ｜ 对密码拿到 32 位令牌 ✅ ｜ 带令牌 200 ✅
- 随笔的**写接口**（增 / 改 / 删），全部挂在 `/api/admin/essays` 下 → 自动被门卫保护
- 完整一圈测试：无令牌新增 401 ✅ ｜ 登录拿令牌 ✅ ｜ 新增（8 → 9 篇）✅ ｜ 修改 ✅ ｜ 删除（9 → 8 篇）✅

### 重要知识点
**1. 认证 vs 授权**
- 认证 = 你是谁（没过 → `401`）；授权 = 你能不能干这件事（不够格 → `403`）

**2. 密码只发一次，之后用令牌**
- 密码是"根钥匙"，泄露代价大；令牌可以**设有效期（现在 12 小时）、可以作废**

**3. 密码存哈希（BCrypt）**
- 不存明文；用 `matches(输入, 哈希)` 比对；单向、"榨汁"后无法反推

**4. 门卫是后端的事，而且只做一次**
- 前端只管"发密码、存令牌"，校验全在后端
- 写法上：**用网址把"读"和"写"分开**
  - `GET /api/essays` → 公开
  - `/api/admin/**` → 一律要令牌
- 门卫只守一条线 → 以后加多少写接口都不用改它

**5. "连接数据库"和"令牌"是两件不同的事**（很容易混）
- 数据库连接：后端**启动时就一直连着**（连接池），用配置里的账号密码
- 令牌：只决定"这次操作允不允许做"
- 一句话：**数据库的门后端一直开着；令牌管的是"谁有权让后端替他做事"。**

**6. 一次请求里有"两段翻译"**
```
前端 JSON ──Jackson──▶ Java 对象 ──Hibernate──▶ SQL ──▶ MySQL
MySQL 的行 ──Hibernate──▶ Java 对象 ──Jackson──▶ JSON ──▶ 浏览器
```
- **Jackson** 管 JSON ↔ Java；**Hibernate** 管 Java ↔ SQL

**7. "写接口"就是"拿到令牌之后，真正改数据库"的那几个接口**

| 动词 | 接口 | 干什么 |
|---|---|---|
| `POST` | `/api/admin/essays` | 新增一篇 |
| `PUT` | `/api/admin/essays/{id}` | 修改某一篇 |
| `DELETE` | `/api/admin/essays/{id}` | 删除某一篇 |

- **为什么都挂在 `/api/admin/` 下？** 因为门卫只守这条线 —— 写接口放进去就自动被保护，安全代码一行都不用写
- 写入的"约定"用一个 `record`（`EssayForm`）表示：`{ writtenOn, title, body }`
- `repository.save(对象)`：**没有 id 就是 INSERT，有 id 就是 UPDATE** —— 同一个方法干两件事

## 踩坑记录（都是真实发生过的）

| 现象 | 原因 | 怎么解决 |
|---|---|---|
| `Port 8080 was already in use` | 上次的后端没退干净 | `taskkill /IM java.exe /F` 清场 |
| `Unable to rename ... .jar`（打包失败） | **程序还在跑，文件被系统锁住** | 先停掉程序再打包 |
| `Non-parseable POM` | `pom.xml` 开头多了字符（手滑） | 看报错的行号，删掉多余字符 |
| 命令行整条不执行 | PowerShell 括号没配对 | 数一遍 `(` 和 `)` |
| 网页看不到新内容 | 浏览器缓存 | `Ctrl + Shift + R`，或给文件换个名字 |
| 命令直接双击 `index.html` 打不开数据 | `file://` 会被浏览器拦 | 用本地服务器，或让后端来提供数据 |
