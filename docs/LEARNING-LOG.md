## 第 1 天 · 2026-09-10

**Q：后端是不是前端和数据库之间的桥梁？**
是。前端只会说 JSON，数据库只懂 SQL，**后端是中间那个既懂两边、又握着钥匙的人**。

**Q：请求 / 响应 / 接口是什么？**
- 请求 = 我发出去的一封信（动词 + 地址 + 内容）
- 响应 = 回信（状态码 200 / 401 / 404…… + 内容）
- 接口 = 约定好的窗口：地址 + 用什么动词 + 会还我什么

**Q：门卫是怎么校验身份和权限的？**
密码只发一次（登录）→ 后端发一张令牌 → 之后每次"写"都带上令牌 → 门卫检查。

**Q：我要看懂所有代码吗？**
不用。记住这几个就够：**实体=表、仓库=取数据、控制器=窗口、门卫=查令牌**；框架内部先当黑盒。

## 第 2 天 · 2026-09-11

**Q：MySQL 的账号密码，能在另一台电脑上同步用吗？**
不能。每台电脑的 MySQL 各自独立，密码也各自独立。
能搬的只有**数据**：导出 `.sql` → 拷过去 → 导入。（想省事，就把两台电脑的密码设成一样。）

**Q：这些内容现在只是在前端显示吗？以后要放进数据库吗？**
现在都写在 `index.html` 里。
以后放进数据库的，是**我会经常改的东西**：随笔、发帖、简介。技能 / 项目 / 教育经历可以放也可以不放。

## 第 3 天 · 2026-09-12

**Q：门卫是后端做的事吗？**
是，全在后端。前端只负责"把密码发过去、把令牌存起来"。

**Q：前端拿到 token，就等于允许连接数据库了吗？**
不是，这是两件事：
- **连接数据库**：后端启动时就一直连着（和令牌无关）
- **令牌**：只决定"这次操作允不允许做"

一句话：**数据库的门，后端一直开着；令牌管的是"谁有权让后端替他做事"。**

**Q：后端会把前端发来的 JSON 翻译成 SQL 吗？**
会，而且是两段翻译：
`JSON →（Jackson）→ Java 对象 →（Hibernate）→ SQL`

**Q：用了 JPA 就不用 SQL 了吗？**
不是不用，是**不用我亲手写**。JPA 照样生成 SQL 发给 MySQL，只是这句 SQL 由它替我写了。

**Q：接下来是不是就是建各种表，重复"把随笔接进数据库"那件事？**
是。同一套配方换内容：**表的设计图 → 仓库 → 窗口**；写接口挂在 `/api/admin/` 下，自动被门卫保护。

**Q："写接口"是什么意思？**
就是"**拿到令牌之后，真正去改数据库**"的那几个接口：
`POST /api/admin/essays`（新增）· `PUT /api/admin/essays/{id}`（修改）· `DELETE /api/admin/essays/{id}`（删除）

## 第 4 天 · 2026-09-13

**Q：后端这么多表，都已经接好了吗？**
一开始只有 `essay`（随笔）走通了全程。今天补上另外两张：
- `profile` —— 我的资料，**永远只有一行**（名字 / 一句话 / 简介 / 头像和背景图的路径）
- `post` —— 发帖（标题 / 正文 / 标签 / 日期）

还差一张可选的 `owner_token`（把令牌存进数据库，重启后端就不用重新登录）。

**Q：什么叫做水平越权（IDOR）？我们是在哪里处理的？**
IDOR = **同样是普通用户，却动了别人的数据**。
最典型的场景：网址里带一个 id，把它改个数字就看到了别人的私密内容：

```
GET /api/memos?userId=1   →（改成）→   GET /api/memos?userId=2
```

根因只有一句：**后端相信了前端说的"我是谁"**。

处理它的是**上一个项目（Cyber-Tunnel）**，不是这个网站：
- 改前：前端传 `userId`，后端照着查 → 改数字就能越权
- 改后：后端签发令牌 → 从令牌里推出**真实的 userId** → 每次查询都加归属条件（`findByIdAndUserId`）
- 记录在那边仓库的 `docs/AUTH-SECURITY.md`

分清两件事（很容易混）：

| | 管什么 | 在哪 |
|---|---|---|
| 认证 / 授权（门卫） | 你是不是站长、**能不能写** | 这个网站：`/api/admin/**` |
| 归属校验（防 IDOR） | **这条数据是不是你的** | Cyber-Tunnel：`findByIdAndUserId` |

这个网站只有一个作者，所以暂时**不需要**归属校验；以后加了"访客留言"或变成多用户，就必须加。
