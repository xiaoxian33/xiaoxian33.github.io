## 第 1 天 · 2026-09-10

**Q：后端是不是前端和数据库之间的桥梁？**
是。前端只会说 JSON，数据库只懂 SQL，**后端是中间那个既懂两边、又握着钥匙的人**。

**Q：请求 / 响应 / 接口是什么？**
- 请求 = 我发出去的一封信（动词 + 地址 + 内容）
- 响应 = 回信（状态码 200 / 401 / 404…… + 内容）
- 接口 = 约定好的窗口：地址 + 用什么动词 + 会还我什么

**Q：门卫是怎么校验身份和权限的？**
密码只发一次（登录）→ 后端发一张令牌 → 之后每次"写"都带上令牌 → 门卫检查。

**Q：我要看懂所有代码吗？**
不用。记住这几个就够：**实体=表、仓库=取数据、控制器=窗口、门卫=查令牌**；框架内部先当黑盒。

## 第 2 天 · 2026-09-11

**Q：MySQL 的账号密码，能在另一台电脑上同步用吗？**
不能。每台电脑的 MySQL 各自独立，密码也各自独立。
能搬的只有**数据**：导出 `.sql` → 拷过去 → 导入。（想省事，就把两台电脑的密码设成一样。）

**Q：这些内容现在只是在前端显示吗？以后要放进数据库吗？**
现在都写在 `index.html` 里。
以后放进数据库的，是**我会经常改的东西**：随笔、发帖、简介。技能 / 项目 / 教育经历可以放也可以不放。

## 第 3 天 · 2026-09-12

**Q：门卫是后端做的事吗？**
是，全在后端。前端只负责"把密码发过去、把令牌存起来"。

**Q：前端拿到 token，就等于允许连接数据库了吗？**
不是，这是两件事：
- **连接数据库**：后端启动时就一直连着（和令牌无关）
- **令牌**：只决定"这次操作允不允许做"

一句话：**数据库的门，后端一直开着；令牌管的是"谁有权让后端替他做事"。**

**Q：后端会把前端发来的 JSON 翻译成 SQL 吗？**
会，而且是两段翻译：
`JSON →（Jackson）→ Java 对象 →（Hibernate）→ SQL`

**Q：用了 JPA 就不用 SQL 了吗？**
不是不用，是**不用我亲手写**。JPA 照样生成 SQL 发给 MySQL，只是这句 SQL 由它替我写了。

**Q：接下来是不是就是建各种表，重复"把随笔接进数据库"那件事？**
是。同一套配方换内容：**表的设计图 → 仓库 → 窗口**；写接口挂在 `/api/admin/` 下，自动被门卫保护。

**Q："写接口"是什么意思？**
就是"**拿到令牌之后，真正去改数据库**"的那几个接口：
`POST /api/admin/essays`（新增）· `PUT /api/admin/essays/{id}`（修改）· `DELETE /api/admin/essays/{id}`（删除）

## 第 4 天 · 2026-09-13

**Q：后端这么多表，都已经接好了吗？**
一开始只有 `essay`（随笔）走通了全程。今天补上另外两张：
- `profile` —— 我的资料，**永远只有一行**（名字 / 一句话 / 简介 / 头像和背景图的路径）
- `post` —— 发帖（标题 / 正文 / 标签 / 日期）

还差一张可选的 `owner_token`（把令牌存进数据库，重启后端就不用重新登录）。

**Q：什么叫做水平越权（IDOR）？我们是在哪里处理的？**
IDOR = **同样是普通用户，却动了别人的数据**。
最典型的场景：网址里带一个 id，把它改个数字就看到了别人的私密内容：

```
GET /api/memos?userId=1   →（改成）→   GET /api/memos?userId=2
```

根因只有一句：**后端相信了前端说的"我是谁"**。

处理它的是**上一个项目（Cyber-Tunnel）**，不是这个网站：
- 改前：前端传 `userId`，后端照着查 → 改数字就能越权
- 改后：后端签发令牌 → 从令牌里推出**真实的 userId** → 每次查询都加归属条件（`findByIdAndUserId`）
- 记录在那边仓库的 `docs/AUTH-SECURITY.md`

分清两件事（很容易混）：

| | 管什么 | 在哪 |
|---|---|---|
| 认证 / 授权（门卫） | 你是不是站长、**能不能写** | 这个网站：`/api/admin/**` |
| 归属校验（防 IDOR） | **这条数据是不是你的** | Cyber-Tunnel：`findByIdAndUserId` |

这个网站只有一个作者，所以暂时**不需要**归属校验；以后加了"访客留言"或变成多用户，就必须加。

## 第 5 天 · 2026-09-14

**Q：前端接上后端，具体做了什么？**
把写在 HTML 里"死"的内容，换成从接口读"活"的。今天接了两个：

- 「关于我」← `GET /api/profile`
- 「随笔」← `GET /api/essays`

配方是同一个：**先让 HTML 里的旧内容顶着（兜底）→ 悄悄去问后端要 → 拿到了再覆盖**。
这叫「**渐进增强**」—— 后端没开的时候，页面照样能看，不会是一片空白。

**Q：数据库和前端是"两种不同的储存形式"，所以中间要有一堆翻译规矩吗？**
对，这就是跨系统的本质：**两个系统说不同的方言，中间必须有翻译官。**

同一篇随笔，会变身 **5 次**：

| 在哪 | 长什么样 | 谁负责翻译 |
|---|---|---|
| ① **MySQL** | 二维表格里的一行，`body` 是一坨纯字符 | — |
| ② **Java 内存** | `Essay` 对象（有属性、有方法）| **Hibernate / JPA**（表 ↔ 对象，叫「映射」）|
| ③ **网络传输** | JSON 文字（这样才能塞进 HTTP 寄走）| **Jackson**（对象 → 文字，叫「**序列化**」）|
| ④ **浏览器 JS** | 普通对象，可以 `p.name` 取值 | **`res.json()`**（文字 → 对象，叫「**反序列化**」）|
| ⑤ **屏幕上** | HTML 标签 + CSS → 像素 | **我写的 `map` / `join`**（数据 → HTML）+ **浏览器**（HTML → 像素，叫「**渲染**」）|

一句话：**表 → 对象 → JSON 文字 → JS 对象 → HTML → 像素**，每一步都要翻译。

> 这些"规矩"的正式名字：
> **格式**（长什么样：JSON / HTML）· **协议**（怎么说话：HTTP）·
> **约定**（怎么命名：`getAvatarPath()` → `avatarPath`）·
> **序列化 / 反序列化**（对象 ↔ 文字）。
>
> 为什么要有 JSON？因为它是**双方都能读懂的中转格式**（数据交换格式）。

**Q：为什么一段文字，到页面上会变成两个段落？**
因为**数据库里根本没有"段落"**，它只存了一串字符，中间夹着两个看不见的**换行符**（`\n`）。

`\n` 不是"反斜杠 + 字母 n"两个字符 —— 它是**一个看不见的字符**的写法，叫换行符。
所以数据库里其实是：`…读数据了。⏎⏎它还顺便…`（两个换行符，看不见，但确实占位置）。

**为什么"两个换行符"就是"一个空行"？** 跟你在记事本里一样：
- 按 **1 次**回车 → 光标到下一行（两行紧挨着）
- 按 **2 次**回车 → 中间空出一行

**⚠️ 关键真相：HTML 会把换行"吃掉"！**
```html
<p>
  第一行
  第二行
</p>
```
浏览器渲染出来是 `第一行 第二行` —— 换行没了，变成一个空格。
（HTML 的规矩：连续的空白，不管是空格、换行还是 Tab，都只当作**一个空格**。）

所以想在网页上换行 / 分段，**不能靠回车，必须靠标签**：

| 标签 | 效果 | 我用在哪 |
|---|---|---|
| `<br />` | **换行**（同一段之内，紧凑）| 「关于我」的简介 |
| `<p>` | **分段**（新的一段，上下有间距）| 「随笔」的正文 |

**Q：`split` 的刀口为什么要写 `/\n\s*\n/` 这么复杂？**

| 符号 | 意思 | 为什么要它 |
|---|---|---|
| `\n` | 一个换行 | 必须有 |
| `\s*` | **零个或多个**空白（空格、Tab）| ⚠️ 有人可能往空行里敲了空格，`\s*` 让这种脏数据也能切对 |
| `\n` | 又一个换行 | 必须有 |

连起来读 = **「换行 → 中间可能有空格 → 换行」= 空行**。
只写 `/\n\n/` 就切不了 `⏎   ⏎` 这种；`\s*` 就是"宽容一点"（防御性写法 —— 不指望输入永远完美）。

**Q：`split` / `map` / `join` 分别干什么？**
三个都是**数组**上的操作，串起来就是一条小流水线：

| 工具 | 干什么 | 类比 | 例子 |
|---|---|---|---|
| `split` | **一条字符串 → 数组**（在"刀口"处剪开）| ✂️ 剪刀 | `"A-B".split("-")` → `["A","B"]` |
| `map` | **数组 → 新数组**（每个元素都过一遍"加工机器"）| 🏭 流水线 | `[1,2].map(n => n*2)` → `[2,4]` |
| `join` | **数组 → 一条字符串**（粘起来）| 🧴 胶水 | `["A","B"].join("")` → `"AB"` |

⚠️ **`map` 里要写函数名，不能带括号**：`map(essayHTML)` ✅ / `map(essayHTML())` ❌
因为我们是把"这台机器"**交给** `map`，不是**现在就开机**（带了括号会立刻执行一次，然后报错）。

**Q：为什么最后一定要 `join`？**
因为 `innerHTML` **只接受一个字符串**，不吃数组。
所以 `list.map(essayHTML).join('')` 读作：**加工成 HTML → 粘成一大块 → 整块塞进页面**。

**Q：随笔分段的完整流程？**

```
① 数据库："如果你…\n\n它还…"            ← 1 条字符串（含 2 个看不见的换行符）
        │  split(/\n\s*\n/)    ✂️ 剪开
        ▼
② 数组：["如果你…", "它还…"]              ← 2 个元素
        │  map(每块包一层 <p>)  🧥 穿衣服
        ▼
③ 数组：["<p>如果你…</p>", "<p>它还…</p>"]
        │  join('')            🧴 粘回去
        ▼
④ 字符串："<p>如果你…</p><p>它还…</p>"
        │  innerHTML = ...     📥 丢给浏览器
        ▼
⑤ 屏幕：两个有间距的段落 ✨
```

**一句话记住：数据库只负责"存字符"，排版是前端用标签"做"出来的。**

**Q：为什么日志里的中文会变成乱码？**
这是更底层的一层翻译出了错 —— **编码**（字符 ↔ 字节）。
写的时候按 **UTF-8** 把"字"编成字节，读的时候却按 **GBK** 去解 —— 规则对不上，就成了鬼画符。

**Q：重启电脑后，为什么页面又连不上后端了？**
因为两者的"启动方式"不一样：

| 东西 | 怎么启动的 | 重启电脑后 |
|---|---|---|
| **MySQL** | 装成了 **Windows 服务**（配了开机自启）| ✅ 自动起来，不用管 |
| **后端 Spring Boot** | 手动跑的**临时进程** | ❌ 就没了 |

👉 所以每次重启电脑后，**双击 `D:\myworks\start-backend.bat`** 把后端启动起来。
看到 `Started SiteServerApplication in xx seconds` 就是好了。
（弹出的黑窗口**不能关** —— 关了后端就停了；最小化没关系。）

**Q：怎么判断"是不是后端没开"？**
先自己排查这三步，别急着改代码：

1. 浏览器直接访问 http://localhost:8080/api/profile —— 打不开就是后端没开
2. 打开 `start-backend.bat` 的窗口，看有没有报错
3. 后端窗口里看到 `Started SiteServerApplication` 才算启动成功
