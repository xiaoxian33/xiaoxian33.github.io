---

## 一、项目定位

**一句话**：一个可无限生长的「赛博个人主页」＝ 像素桌面 OS 外观 ＋ 数据驱动的作品集 ＋ 只有作者能进的秘密管理端 ＋ 会像我说话的 AI 分身。

它不想解决"怎么把简历排版得好看"，它想解决一个更根本的问题：

> **大多数个人主页，做出来那天就是它的巅峰。**
> 加一个项目要重写页面，于是慢慢烂尾。
> 我要的是一个**不需要重构就能一直长大**的载体。

## 三、总体架构

```
┌────────── 前端：纯静态 · GitHub Pages 免费托管 ──────────┐
│  桌面 OS 外壳 + 窗口系统 + 作品/技能/地图/日志视图        │
│  数据源：data/*.json（无构建、无框架、无依赖）            │
│  隐藏入口：Ctrl+Shift+O → 终端 → 主人密钥 → 同页变身      │
└───────────────────────────┬──────────────────────────────┘
                            │ fetch（只有"手账 / 分身"会走这里）
┌───────────────────────────▼──────────────────────────────┐
│  后端：Spring Boot + JPA + MySQL（第二阶段 / M4）         │
│  认证：主人密钥（BCrypt 哈希）+ 设备令牌（多端共存可踢）   │
│  业务：/api/posts 手账 · /api/uploads 图片 · /api/npc 分身 │
│  部署：本机 + ngrok（临时） → 云服务器 / 域名（后期）      │
└──────────────────────────────────────────────────────────┘
```

**为什么这么切？**

- 静态部分负责**帅、快、免费、无限扩充**，就算后端停机，访客也照样能看到完整的作品集；
- 后端只负责**"只有我能写"**的那部分（手账、上传、分身），故障半径小；
- 前端不做鉴权判断的"安全"假设：**能不能写，由后端说了算**。

## 四、代码分层约定

| 文件 | 职责 | 改它的时机 |
|---|---|---|
| `index.html` | 桌面外壳结构（开机层 / 桌面层 / 窗口层 / 任务栏） | 几乎不用改 |
| `assets/css/os.css` | 像素赛博主题（变量化配色） | 想换皮肤时 |
| `assets/js/data.js` | 读 `data/*.json`，统一转义与日期格式 | 加新数据源时 |
| `assets/js/views.js` | 每个窗口的内容视图（`render()` + `mount()`） | 加新窗口模块时 |
| `assets/js/os.js` | 桌面内核：开机动画 / 图标 / 窗口管理器 / 任务栏 | 改交互时 |
| `assets/js/secret.js` | 隐藏管理模式：作弊码 + 终端 +（将来的）认证 | 改管理端时 |
| `data/**` | 全部内容 | **日常扩充只动这里** |

**视图契约**：一个视图对象就是

```js
{ title, icon, w, h, bodyClass?, render() { return '<html>' }, mount(el) { /* 可选：绑事件 */ } }
```

新增窗口 = 写一个视图 + 在 `os.js` 的 `APPS` 里登记一行。没有构建步骤，没有依赖，改完刷新即可。

| 阶段 | 交付物 | 验收标准 | 状态 |
|---|---|---|---|
| **M0 建仓** | 仓库 + 目录 + README + GitHub Pages | 打开 `https://xiaoxian33.github.io` 能看到页面 | 进行中 |
| **M1 桌面壳** | 开机自检动画 → 桌面 → 图标 → 可拖拽窗口 → 任务栏 | 单击图标能开窗、拖动、关闭，任务栏与时钟联动 | ✅ 已完成 |

| **M3 秘密入口** | `Ctrl+Shift+O` → 像素终端 → 静默失败 →（预留）同页变身 | 访客怎么点都发现不了；终端只在暗号下出现 | ✅ 入口已完成 |
| **M4 后端** | Spring Boot：主人密钥 + 设备令牌认证 + 手账 CRUD + 图片上传 | 真机发一条手账，游客只能看不能改 | 待做 |
| **M5 亮点层** | 成就系统 / 访客足迹 / 更多彩蛋 | 每个亮点都能单独演示 | 待做 |

每个阶段都会被记进 `data/changelog.json`——**做完了就发一次版**，这本身就是这个站点的产品哲学。

## 六、技术选型与理由

| 选择 | 为什么 |
|---|---|
| 原生 HTML/CSS/JS，零框架零构建 | 加载快、可直接双击看、GitHub Pages 零配置；先把原生能力打穿再上框架 |
| `data/*.json` 驱动 | 「扩充」的成本必须接近零，否则一定会烂尾 |
| GitHub Pages | 免费、稳定、和仓库同源，推上去即上线 |
| Spring Boot（第二阶段） | 复用 Cyber-Tunnel 的经验（分层 / JPA / 拦截器 / Token），学习曲线为零 |
| 前端不引入大模型 SDK | AI 分身的密钥必须留在服务端，前端只调用自家接口 |

## 七、数据规范

**作品 `data/projects/<id>.json`**

```json
{
  "id": "cyber-tunnel",
  "name": "Cyber-Tunnel",
  "subtitle": "用药记录与心得分享社区",
  "emoji": "💊",
  "status": "done | building | planned | archived",
  "featured": true,
  "role": "全栈独立开发",
  "period": "2026 春 · 大二下课程项目",
  "tagline": "一句话钩子",
  "summary": "它是什么",
  "stack": ["Java 17", "Spring Boot"],
  "links": [{ "label": "源码仓库", "url": "https://…" }],
  "highlights": ["亮点一", "亮点二"],
  "story": { "problem": "想解决什么", "pits": ["踩过的坑"], "upgrade": ["怎么升级的"] },
  "learned": "我从里面带走了什么",
  "future": ["如果还有下一次"]
}
```

**技能 `data/skills.json`**：`branches[].skills[]`，每个技能 `{ name, level: lit|learning|locked, note, evidence? }`

**地图 `data/roadmap.json`**：`zones[]`，每片区域 `{ id, name, status: done|building|planned, icon, desc }`

**日志 `data/changelog.json`**：`{ current, note, entries: [{ version, date, title, items[] }] }`

## 八、扩充手册（日常只需要看这一节）

```bash
# 1) 加一个作品
#    新建 data/projects/xxx.json（照抄 cyber-tunnel.json），然后：
node tools/index-projects.mjs

# 2) 本地预览
start.bat            # 或 python -m http.server 8080

# 3) 发布
git add -A && git commit -m "feat(projects): add xxx" && git push
```

## 九、约定

- **提交信息**沿用 Conventional Commits：`feat(scope): ...`、`docs: ...`、`fix(scope): ...`
- **密钥与密码永不入库**：一律走环境变量（参考 Cyber-Tunnel 的 `${DB_PASSWORD:...}` 写法）
- **公开仓库不写隐私**：真实联系方式由作者自行决定是否保留
- **素材**：图片建议压缩后放 `assets/img/`，避免仓库膨胀
