# 我到底要掌握多少（2026-09-17）

> 累的时候就翻这一页。结论先说：**真正需要你掌握的，大约 20%。**
> 剩下那 80% 不是"必须学会"，它们只在你**想改某件事**的时候才需要。

## 第一圈 · 必须会（约 20%）—— 决定"网站能不能用、我能不能改内容"

1. **让站点活着**：MySQL 开着 → 启动后端 → 打开网站
2. **进编辑模式**：↑ + ← → 输密码
3. **改内容**（全在弹窗里点，跟数据库、代码无关）：
   发帖 / 改帖 / 删帖 / 写随笔 / 改随笔 / 改资料 / 传图片
4. **改死文字和样式**：`index.html`（页面上的字）、`assets/css/style.css`（颜色、大小）
5. **推上去**：`git add` → `commit` → `push`（GitHub Pages 自动更新）
6. **出问题看两处**：页脚写着"后端已连接"吗？浏览器 F12 → Network（哪条请求红了）/ Console（有没有红字）

**这一圈会了，你的网站就完全归你管了。**

## 第二圈 · 会用就行（约 30%）—— 不用背，会查

| 想知道什么 | 去哪查 |
|---|---|
| 接口要什么字段、还什么字段 | `docs/API.md` |
| 哪个文件干什么活 | `docs/代码结构.md` |
| 每天做了什么、踩过什么坑 | `docs/LEARNING-LOG.md` |
| 什么时候能给别人看 | `docs/上线清单.md` |
| 令牌是什么 | 脑子里有"一张临时通行证，重启后端就作废"就够 |

## 第三圈 · 可以先不管（约 50%）—— 需要时再学，或者直接交给 Cline

- 外键约束 / 多态关联 / 索引 / `EXPLAIN`
- View 那一层为什么存在（文档里那两段看得懂就够）
- CORS / 事务 / 并发 / 连接池 / 消息队列
- 部署细节（Nginx、systemd、HTTPS 证书、备份脚本）
- 前端细节（事件委托、FormData、缓存、防抖…）

**这一圈整圈跳过，网站照样跑，你也照样能用。**

## 关于你问的那句："不是轮到代码来做了吗，怎么还叫省代码？"

**你的直觉是对的** —— 数据库不帮你盯了，那些活确实落到代码头上。所以准确说法是：

- **省的**：一整套重复的东西（重复的表、重复的查询、两处一模一样的"存图/删图"代码）
- **不省的**：操心 —— 顺序要自己对、删除要自己级联清理、索引要自己加、类型拼错要自己防
- **净账**：大概"少写几十行，多操一点心"

而且那一点点好处，是**"以后加第三种内容（比如项目配图）不用再建表、不用再写一遍"**。
对你这个规模的小站，**两种做法都完全可行**，差异也就几十行。

👉 所以"多态关联"这条**不是必须的**，纯属我多讲的知识点。你完全可以不深究。

## 现在什么都不用决定

项目停在一个干净、能用、已经上线的状态。
- 第三圈的东西，**不学也不影响网站运行**
- 下一步（项目页 / 部署）也没有时间限制
- 你唯一需要记住的一句话：**出问题先看页脚和 F12，然后来找我**
