## 🟢 第一圈 · 地基 —— 这一圈会了，网站就完全归你管

1. **让站点活着**：MySQL 开着 → 启动后端 → 打开网站
2. **进编辑模式**：↑ + ← → 输密码
3. **改内容**（全在弹窗里点，跟数据库、代码无关）：
   发帖 / 改帖 / 删帖 / 写随笔 / 改随笔 / 改资料 / 传图片
4. **改死文字和样式**：`index.html`（页面上的字）、`assets/css/style.css`（颜色、大小）
5. **推上去**：`git add` → `commit` → `push`（GitHub Pages 自动更新）
6. **出问题看两处**：页脚写着"后端已连接"吗？浏览器 F12 → Network（哪条请求红了）/ Console（有没有红字）

# 📜 技能点全录

## 第 1 组 · 后端骨架（Java + Spring）

### 1. 分层架构（Layered Architecture）
- **人话**：一个请求进来，每一层只管一件事 —— 接请求 → 做事 → 查表 → 表长什么样。
- **用在哪**：`PostController`（接）→ `ImageService`（做事）→ `ImageRepository`（查）→ `Post.java`（表）
- **想挖**：MVC、Service 层什么时候可以不要、"贫血模型"

### 2. 依赖注入 / 控制反转（DI / IoC）
- **人话**：需要用的东西**不自己 new**，写在构造器参数里，Spring 负责塞给你。
- **用在哪**：每个 Controller / Service 的构造器，例如 `public ImageService(ImageRepository repository)`
- **想挖**：Spring Bean 生命周期、构造器注入 vs 字段注入、为什么官方推荐构造器

### 3. 注解驱动开发（Annotation）
- **人话**：注解 = **贴给框架看的便利贴**。你贴上去，框架在背后替你接请求、建表、开事务。
- **用在哪**：`@RestController` `@Entity` `@Table` `@Service` `@Transactional` `@Value` `@CrossOrigin`
- **想挖**：Java 反射（注解能起作用全靠它）、`@Component` 家族的区别

### 4. ORM 与实体映射（JPA / Hibernate）
- **人话**：写一个类 = 设计一张表；改类里的字段 = 改表结构。
- **用在哪**：`Post.java` / `Essay.java` / `Image.java`；`ddl-auto=update` 让表**自动建、自动加列**
- **想挖**：ORM 阻抗失配、`ddl-auto` 各档位（**上线前必须从 update 换掉**）、`@Column` / `@GeneratedValue`

### 5. 派生查询（Query by method name）
- **人话**：方法名怎么写，就是什么查询 —— 不用写 SQL。
- **用在哪**：`findByOwnerTypeAndOwnerIdOrderBySortOrderAsc(...)`、`findAllByOrderByPublishedAtDesc()`
- **想挖**：Spring Data JPA 方法名语法、`@Query`、分页 `Pageable`

### 6. 事务（Transaction / @Transactional）
- **人话**：一组操作"要么全成、要么全不做"。删一半留一半，比全不删更糟。
- **用在哪**：`ImageService.replace()` 和 `removeAll()`（先删旧图记录、再写新记录）
- **想挖**：ACID、隔离级别、`@Transactional` 在同类内部调用会失效的坑

## 第 2 组 · 接口设计（REST + 契约）

### 7. 资源化 URL + HTTP 动词（REST）
- **人话**：网址写"**东西**"（`/api/posts`），动作交给方法：GET 读、POST 建、PUT 改、DELETE 删。
- **用在哪**：`PostAdminController` 上的四个 `@XXXMapping`，同一个网址 `/api/admin/posts` 配四种动作
- **想挖**：REST 成熟度模型、PUT vs PATCH、为什么不写 `/getPostById` 这种网址

### 8. 接口契约（Contract）
- **人话**：前后端各写各的，唯一靠得住的是那份"**字段名 + 类型 + 失败情形**"的清单。
- **用在哪**：`docs/API.md`；前端的 `postFromApi()` 就是照着它写的（第 5 天那次"对不上账"的教训）
- **想挖**：OpenAPI / Swagger、契约测试、为什么字段名要一次定死

### 9. 字段更新语义的三种设计（最容易被忽略的一课）
- **人话**："没传这个字段"到底算不算"清空"？**必须事先讲清楚**，否则会出现"只改标题，标签被清空"这种事。
- **用在哪**：`PostAdminController.update` —— `body`/`publishedAt` 是"非 null 才更新"、`title`/`tags` 是"无条件覆盖"、`images` 是"不带就不动"；三条规则都写在 API.md 里
- **想挖**：PUT vs PATCH、JSON Merge Patch、乐观锁（`version` 字段）

### 10. 跨域 CORS
- **人话**：浏览器规定"网页只能问自己家的后端"；跨站要后端**点头**（回一个 CORS 头）才放行。
- **用在哪**：每个 Controller 上的 `@CrossOrigin(origins = "*")` —— 学习阶段全放开，**上线前要收紧**
- **想挖**：同源策略、预检请求（OPTIONS）、为什么"接口在 Postman 里能通、网页里不通"

### 11. 语义化状态码 + 统一错误形状
- **人话**：400 是"你发的东西有问题"、401 是"通行证没带"、404 是"没这东西"、500 是"我炸了"；而且错误要带**一句人话**给用户看。
- **用在哪**：`UploadController` 返回 `{"ok":false,"message":"图太大了：6144KB，一张最多 5MB"}`；前端 `authFetch` 把 `message` 直接弹到提示条
- **想挖**：RFC 7807（Problem Details）、全局异常处理 `@ControllerAdvice`

## 第 3 组 · 数据库（MySQL）

### 12. 一对多关系建模
- **人话**：一条内容配多张图 → **另开一张子表**，每一行写清"我属于谁"。
- **用在哪**：`image` 表（一张图 = 一行，`owner_id` 指向它属于哪条内容）
- **想挖**：一对多 / 多对多的三种建表方式、中间表

### 13. 主键 / 排序 / 时间戳三件套
- **人话**：`id` 认人、`sort_order` 排版、`created_at` 记历史 —— 一张装"多条内容"的表，基本功。
- **用在哪**：`image` 表三样齐全；`Essay.sortOrder` 决定随笔的先后
- **想挖**：自增 id vs UUID、`updated_at` 该由谁写、软删除（`deleted_at`）

### 14. 范式与反范式的取舍
- **人话**：教科书教你拆表，但像"标签"这种**只用来显示**的小东西，存成一个 `"学习,Java"` 字符串更省事。
- **用在哪**：`Post.tags` 就是字符串（不是标签表）；前端 `split(',')` 切成数组来显示
- **想挖**：三范式、反范式、**什么时候必须拆**（比如要"按标签搜索"）

### 15. 索引与全表扫描
- **人话**：索引像书的目录。没有目录，数据库只能**一页页翻**（全表扫描）。查询里用到的列才需要索引，但索引会让写入变慢。
- **用在哪**：`image` 表目前**没有** `(owner_type, owner_id)` 索引 —— 我记下的一笔欠账（数据多了会慢）
- **想挖**：B+ 树、复合索引的"最左前缀"、`EXPLAIN` 看执行计划

### 16. 外键约束与级联删除
- **人话**：数据库版的"这本书必须真的存在才能借"；还能规定"书被删了，借阅记录跟着删"。
- **用在哪**：**你的库现在一个外键都没有**（我实测查过）—— 因为多态关联用不了外键，一致性改由 `ImageService` 用代码保证
- **想挖**：`FOREIGN KEY`、`ON DELETE CASCADE` / `RESTRICT`、`CHECK` 约束、外键的性能代价

### 17. 多态关联（Polymorphic Association）
- **人话**：一个"属于谁"的列**同时**能指向帖子或随笔（用 `owner_type` 标出类型），代价是数据库的外键用不了。
- **用在哪**：`image` 表；`ImageService.POST` / `ESSAY` 两个常量；图片功能计划里的"一张通用表"
- **想挖**：单表继承（STI）、类表继承（CTI）、为什么 ORM 社区对它又爱又恨

### 18. 字符集与排序规则（Charset / Collation）
- **人话**：存中文要选对字符集（`utf8mb4`），否则就是"锟斤拷"；排序规则决定"怎么比较、怎么排序"。
- **用在哪**：建表语句末尾的 `DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci`；后端 properties 里的 UTF-8 两行
- **想挖**：`utf8` vs `utf8mb4`（表情符号必须后者）、连接串里的 `characterEncoding`

## 第 4 组 · 认证与安全

### 19. 认证（Authentication）与授权（Authorization）
- **人话**：认证 = "你是谁"，授权 = "你能干什么"。**门卫只管认证**。
- **用在哪**：`OwnerAuthInterceptor` 只管"有没有带有效令牌"；`/api/admin/**` 这个范围就是授权
- **想挖**：RBAC（按角色授权）、为什么用拦截器而不是每个接口里写 if

### 20. 令牌认证（Token / Bearer）
- **人话**：登录一次换一张"临时通行证"，之后每个请求都要出示；过期就得重新登录。
- **用在哪**：`OwnerAuthService`（`UUID` + 内存 `Map<令牌, 过期时间>`）；前端 `readToken()` + `Authorization: Bearer xxx`
- **想挖**：JWT vs 服务端 Session、令牌该存哪（内存 / 数据库 / Redis）、为什么重启就失效

### 21. 密码哈希（BCrypt）
- **人话**：数据库里**永远不存明文密码**，存它的单向指纹；指纹算不回去，但能比对。
- **用在哪**：`OwnerAuthService` 用 BCrypt 处理 `app.owner.password`
- **想挖**：加盐（salt）、为什么 MD5/SHA1 不能用、彩虹表

### 22. 服务端永不信任前端
- **人话**：前端校验只是"帮用户少犯错"；**真正的防线在后端**，因为前端代码用户随时能改。
- **用在哪**：正文非空的检查前后端各做一遍；上传接口把扩展名和 `Content-Type` 各查一次
- **想挖**："客户端校验为体验，服务端校验为安全"

### 23. 文件上传安全
- **人话**：上传是攻击面最大的功能之一 —— 类型、大小、文件名，一个都不能信。
- **用在哪**：`UploadController`：类型双重校验 + 单张 5MB + **文件名后端随机生成**（防中文/空格/`../` 目录穿越）
- **想挖**：目录穿越、内容嗅探、为什么上传目录要放在 Web 根目录外、图片马

### 24. 密钥与配置分离
- **人话**：密码**不进仓库**，只放在服务器 / 本机的私有配置里。
- **用在哪**：`application-local.properties`（密码）+ `.gitignore` 排除它；`application.properties` 只放公共设置
- **想挖**：环境变量、密钥管理服务（Vault/KMS）、万一真提交了怎么补救（`git filter-repo`）

### 25. XSS 与转义
- **人话**：把用户输入当 HTML 拼进页面，等于让别人在你家墙上乱写（甚至偷走令牌）。
- **用在哪**：前端 `esc()`（把 `& < > " '` 变成实体）；正文用 TEXT 存原文，不做富文本
- **想挖**：存储型 / 反射型 XSS、`textContent` vs `innerHTML`、CSP 内容安全策略

## 第 5 组 · 前端与浏览器

### 26. DOM 与渲染（innerHTML 重绘）
- **人话**：页面上每一块都是一个"节点"；`innerHTML = '一段 HTML 文字'` 就是**把里面的东西全换掉**。
- **用在哪**：`mountList` 的 `draw()`、`essayHTML`、`drawImages()`
- **想挖**：DOM 树、重排与重绘、为什么大列表会卡、虚拟 DOM（React 的起点）

### 27. 事件冒泡与事件委托
- **人话**：点击会从最里面的元素**一路往上冒泡**。所以不用给每个按钮绑事件 —— 绑在父级/`document` 上，点谁都能收到。
- **用在哪**：列表里的 ✏️🗑️（列表每次重画，逐个绑会失效）；`e.target.closest('[data-edit-post]')`
- **想挖**：捕获/冒泡三阶段、`stopPropagation`、`dataset` 自定义数据

### 28. 异步与 Promise
- **人话**：网络请求不会"原地等"，它先返回一个"承诺"（Promise），成功走 `.then`、失败走 `.catch`。
- **用在哪**：`authFetch(...).then(...).catch(...)`；`savePostForm` 里"保存成功后再重新拉列表"
- **想挖**：事件循环（Event Loop）、`async/await`、竞态（两次请求谁先回来）、`Promise.all`

### 29. 请求封装（管道模式）
- **人话**：把"每个请求都要做的事"（带令牌、转 JSON、看状态码、处理 401）收进一个函数，别处只填"不同的部分"。
- **用在哪**：`authFetch()` + 8 个 `api*` 动作；`imgUrl()` 是同一招用在"路径翻译"上
- **想挖**：拦截器（Axios interceptor）、重试与超时、断路器

### 30. File API 与上传交互
- **人话**：`<input type="file" multiple accept="image/*">` 拿到的是**文件列表**；要把它包成 `FormData` 才能发。
- **用在哪**：隐藏的 `#postImageInput` + `apiUploadImage(file)`；`accept` 限制可选类型
- **想挖**：`FileList` / `Blob`、`FileReader`（本地预览不占服务器）、拖拽上传、分片上传

### 31. 浏览器缓存与版本号（`?v=`）
- **人话**：浏览器会把 JS/CSS 缓存起来；你改了代码但文件名没变，用户看到的可能还是旧版本 —— 所以要给它加个版本号"强制换新"。
- **用在哪**：`index.html` 里的 `style.css?v=20260917d` / `app.js?v=20260917d`（每次改完就 +1）
- **想挖**：强缓存 vs 协商缓存、`Cache-Control` / `ETag`、构建工具的内容哈希

### 32. 优雅降级（Graceful Degradation）
- **人话**：后端挂了、接口报错，页面**不能白屏**，要保留还能看的内容，并告诉用户"暂时拿不到"。
- **用在哪**：`loadEssays` / `loadPosts` 失败时只 `console.warn`，不覆盖页面里写好的内容；页脚"后端未连接"
- **想挖**：加载态 / 空态 / 错误态三态设计、骨架屏

## 第 6 组 · 工程化与协作

### 33. Git 工作流
- **人话**：小步提交、每条消息说清"干了什么"；**密码和垃圾文件不能进仓库**。
- **用在哪**：`git add -A` → `commit -m "feat(...): ..."` → `push`；`.gitignore` 排除 `application-local.properties`、`target/`、`server/uploads/`
- **想挖**：分支模型（main + feature）、`git diff --stat`、`git log --oneline`、rebase vs merge

### 34. 构建与依赖管理（Maven / Wrapper）
- **人话**：`mvnw` 是"随项目携带的构建工具"，别人 clone 下来不用先装 Maven 就能编译。
- **用在哪**：`server/mvnw.cmd`；`pom.xml` 声明依赖；`mvnw -q -DskipTests compile` 编译
- **想挖**：依赖坐标（groupId/artifactId/version）、scope（compile/test）、打包成 jar 与 `package`

### 35. 配置外部化与多环境
- **人话**：同一份代码，在"我电脑上"和"服务器上"要用不同数据库 —— 所以配置要能**从外面塞进来**。
- **用在哪**：`application.properties`（公共）+ `application-local.properties`（私有）；`@Value("${app.upload-dir}")`
- **想挖**：profile（`application-prod.properties`）、环境变量优先级、十二要素应用（12-Factor）

### 36. 自动化测试与验证手段
- **人话**：人眼点界面容易漏；把"该成立的事"写成**清单**，让机器一遍遍跑。
- **用在哪**：`curl` 打接口逐条断言；无头浏览器（Edge `--headless --dump-dom`）点界面后把结果写进 `<title>` 回读
- **想挖**：单元测试（JUnit）、`MockMvc`、端到端测试（Playwright / Cypress）、测试金字塔

### 37. 调试方法论
- **人话**：**先看证据，再猜原因**；一次只改一个变量。
- **用在哪**：把请求日志埋进 `fetch` 包装（"哪条请求红了"一眼看到）；用 MySQL 查"数据库里到底有没有"；对照实验（去掉某一步看还错不错）
- **想挖**：二分法定位、`console.trace`、断点调试、日志分级

### 38. 文档驱动（把记忆放到纸上）
- **人话**：凡是"约定"，就该写在文件里，而不是靠脑子记 —— 记忆会错，文件不会。
- **用在哪**：`docs/API.md`（接头点）、`docs/代码结构.md`（谁是干嘛的）、`docs/LEARNING-LOG.md`（每天学了什么）、这份文件
- **想挖**：ADR（架构决策记录）、README 该写什么、注释该写"为什么"而不是"做什么"

## 第 7 组 · 部署与运维（就快用到）

### 39. 静态托管与混合内容
- **人话**：前端放在 GitHub Pages（https），后端在你电脑上（http）—— 浏览器把"https 网页调 http 接口"当**混合内容**，可能直接拦掉。
- **用在哪**：现在能用是因为"localhost 被浏览器当成安全来源"；**换成服务器 + 域名时必须上 HTTPS**
- **想挖**：混合内容拦截、localhost 特例、为什么 CORS 报错和混合内容报错长得不一样

### 40. 反向代理（Nginx）
- **人话**：外面只开 80/443，让 Nginx 把 `/api/**` 转给后面的 8080 —— 业务端口不直接暴露。
- **用在哪**：上线清单里的 `https://api.你的域名/api/** → http://127.0.0.1:8080`
- **想挖**：反向代理 vs 正向代理、`proxy_pass`、负载均衡

### 41. 进程守护与日志
- **人话**：SSH 一关你的程序就没了 —— 所以要把它交给系统看守（崩了自动拉起、开机自启）。
- **用在哪**：上线清单里的 systemd 服务 + `journalctl -u site-server -f`
- **想挖**：systemd unit 文件、Docker、日志轮转（logrotate）

### 42. HTTPS 证书
- **人话**：免费的 Let's Encrypt 证书 + 自动续期，别让证书过期（过期 = 全站红色警告）。
- **用在哪**：上线清单的 `certbot` 步骤
- **想挖**：证书链、TLS 握手、自动续期定时任务

### 43. 数据库备份
- **人话**：**不备份 = 数据随时可以消失**。定时导出，而且**要试过能不能恢复**。
- **用在哪**：上线清单里的 `mysqldump` + crontab；图片目录也要一起备（数据库只有路径）
- **想挖**：全量 vs 增量、binlog、异地备份、`3-2-1` 原则

### 44. 磁盘增长与清理
- **人话**：上传的图片只会越来越多；删了内容，**磁盘上的文件不会自己消失**。
- **用在哪**：`server/uploads/` 现在会积累孤儿文件（选完图没保存 / 删内容后留下）
- **想挖**：磁盘配额、定时清理任务、对象存储的生命周期规则

## 第 8 组 · 性能与扩展（等有量再说）

### 45. N+1 查询
- **人话**：读 10 条帖子，如果"每条再单独查一次图片"，就是 11 次查询 —— 这叫 N+1。
- **用在哪**：`PostController.list()` 里"**一次**把所有图查出来、再按 owner 分组"就是为了躲开它（`ImageService.pathsByOwner`）
- **想挖**：JOIN vs 分批查询、Hibernate 的 `fetch join`、慢查询日志

### 46. 缓存策略
- **人话**：同一个东西不必每次都重新算 / 重新传；但要考虑"什么时候让它过期"。
- **用在哪**：`WebConfig` 给 `/uploads/**` 设了 `CachePeriod(3600)`；前端用 `?v=` 控制 JS/CSS 缓存
- **想挖**：HTTP 缓存头（`Cache-Control`/`ETag`）、CDN、服务端缓存（Redis）

### 47. 对象存储（OSS / COS）
- **人话**：图片别都堆在自己服务器上 —— 交给云存储，省带宽、还能挂 CDN。
- **用在哪**：现在的做法是"存本地磁盘"，上线后建议换（`UploadController` 里只有"存哪里"这一处要改）
- **想挖**：直传（前端拿到签名后直接传云）、跨域配置、防盗链

### 48. 连接池与并发
- **人话**：每个请求都要连数据库，连接很贵 → 用一个小池子复用（HikariCP）。
- **用在哪**：Spring Boot 默认已经配好了；以后压测时会碰到"池子满了"
- **想挖**：连接池参数（最大连接数）、线程模型、限流

### 49. 图片压缩与缩略图
- **人话**：手机拍的照片好几 MB，页面上却只显示 84×84 —— 传原图是浪费。
- **用在哪**：现在**没做**（前端只限制了 5MB）；列表里用 CSS 缩到 84px 显示
- **想挖**：WebP/AVIF、服务端缩略图（Thumbnailator）、`<img srcset>` 响应式图片

## 🧪 10 个动手练习（把上面的招式真打一遍）

按"从易到难"排，每个都能在 10~30 分钟内做完，做完你就真的会了：

1. **改一个数字，体会"契约要三处同步"**：把上传上限从 5MB 改成 3MB。
   要改的地方：后端 `UploadController.MAX_BYTES`、`application.properties` 里的 6MB、前端 `IMG_MAX_MB`、`docs/API.md`。少改一处会怎样？去试试。
2. **给索引补课**：给 `image(owner_type, owner_id)` 加索引，用 `EXPLAIN` 看前后差别（数据少时看不出，可以先插 1000 行假数据）。
3. **体会"没有外键"**：往 `image` 插一条 `owner_id = 99999` 的脏数据 → 打开网站看有没有异常 → 再删掉它。
4. **体会"接口形状可以自己定"**：在 `PostView` 里加一个现算的 `excerpt`（body 前 60 字），前端删掉 `makeExcerpt()`。
5. **写个清理脚本**：对比 `uploads` 目录和 `image` 表，把"没人认领的文件"列出来（先只打印、别删）。
6. **让上传一次收多张**：把 `MultipartFile` 改成 `MultipartFile[]`，前端一次发好几张（体会后端接口形状变化的代价）。
7. **把令牌搬进数据库**：新建一张 `token` 表 → 重启后端不再掉线（体会"内存 vs 持久化"）。
8. **看事务回滚**：在 `ImageService.replace()` 中间故意抛个异常，看旧图片记录是不是**没有**被删掉。
9. **看加载态**：用 F12 把网络限速成 Slow 3G，刷新页面 —— 现在的界面会不会"干等"？想想怎么改。
10. **搬家演练**：把 `app.upload-dir` 指到别的目录（比如 `D:/site-uploads`），重启后端，传一张图 —— 体会"路径配置"这件事。

## 🔍 案例：那次"到底是省代码还是费代码"的讨论

**你的直觉是对的** —— 数据库不帮你盯了，那些活确实落到代码头上。所以准确说法是：

- **省的**：一整套重复的东西（重复的表、重复的查询、两处一模一样的"存图/删图"代码）
- **不省的**：操心 —— 顺序要自己对、删除要自己级联清理、索引要自己加、类型拼错要自己防
- **净账**：大概"少写几十行，多操一点心"

而且那一点点好处，是**"以后加第三种内容（比如项目配图）不用再建表、不用再写一遍"**。
对你这个规模的小站，**两种做法都完全可行**，差异也就几十行。

👉 所以"多态关联"这条**不是必须的**，纯属我多讲的知识点。你完全可以不深究。
