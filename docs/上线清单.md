# 🚀 离上线还差什么 · 完整清单

> **现在的状态**：前端在 GitHub Pages 上能看；后端只在你自己的电脑上跑；
> 数据已经进了 MySQL 三张表（`essay` / `profile` / `post`），读写接口全部验证通过。

## 一句话结论

你还差的不是"功能"，是**整条链路**：

```
写死的页面  →  从数据库读  →  部署到云服务器  →  域名 + HTTPS  →  访客真的看到
    ✅         ⬜ 下一步         ⬜                 ⬜
```

**必做的只剩 4 件**（做完就能"给别人看"）：

| # | 事情 | 大概多久 | 为什么非做不可 |
|---|---|---|---|
| 1 | 前端接上接口 | 2~3 天 | 现在页面内容还写死在 HTML 里，改了数据库页面上不会变 |
| 2 | 后端搬上云服务器 | 1~2 天 | 现在后端只在你电脑上，别人访问不到 |
| 3 | 域名 + HTTPS | 半天 | 光有 IP 不像"网站"；而且 GitHub Pages 是 https，去调 http 接口会被浏览器直接拦掉 |
| 4 | 图片上传 | 半天 | 不然"换头像 / 换背景"要改代码 |

其余的都属于"上线以后慢慢加固"，**不挡上线**。

## 一、必做（不做就上不了线）

### 1. 前端接上接口 ← 下一步做这个

- **登录**：删掉 `assets/js/app.js` 里的本地密码 `admin123`，改成 `POST /api/login`，把令牌存起来（`localStorage`）
- **读**：随笔页 → `GET /api/essays`；发帖页 → `GET /api/posts`；首页资料/头像 → `GET /api/profile`
- **写**：编辑模式里真的去调 `/api/admin/**`，每个请求都带 `Authorization: Bearer <令牌>`
- **令牌过期怎么办**：后端会回 401 → 前端自动退回"访客模式"，提示重新登录（别白屏）
- **连不上后端怎么办**：要有"加载中"和"暂时连不上"的样子，不能干等

### 2. 后端搬上云服务器

- 买一台：2 核 2G 就够（学生机最便宜）
- 装环境：**JDK 21** + **MySQL 8** + **Nginx**
- 打包上传：`.\mvnw.cmd package` → `target\site-server-0.0.1-SNAPSHOT.jar` → 传到服务器
- **用 systemd 守护**：开机自启、崩了自动重启（否则一关 SSH 服务就没了）
- 数据搬过去：本地 `mysqldump` 导出 → 服务器导入（步骤见 [MYSQL-SETUP.md](MYSQL-SETUP.md)）
- **配置分开**：服务器上放一份 `application-prod.properties`（数据库地址、密码），密码**不要写进仓库**
- **防火墙只开 22 / 80 / 443**：8080 别直接对外，让 Nginx 转发过去
- Nginx 反向代理：`https://api.你的域名/api/**` → `http://127.0.0.1:8080`
- 看日志：`journalctl -u site-server -f`
- **定时备份**：加一条 crontab，每天 `mysqldump` 一份（出事时能救命）

### 3. 域名 + HTTPS

- 买域名（一年几十块），加一条 A 记录指向服务器 IP
- 证书用 **Let's Encrypt**（免费），`certbot` 一条命令，Nginx 配好 443
- ⚠️ **前端记得改成 https 的接口地址**：GitHub Pages 走 https，如果去调 `http://…:8080`，浏览器会当成"混合内容"**直接拦掉**
  （这个坑我踩过：接口明明是通的，但浏览器根本不发请求）
- 顺手配 http → https 自动跳转

### 4. 图片上传（想"能换头像"就必须做）

- 最小做法：后端收文件（multipart）→ 存到服务器目录 → 返回一个 URL → 写进 `profile.avatarPath`
- 更好做法：传到**对象存储**（OSS / COS），不占服务器带宽，还能挂 CDN
- 不管哪种：**都要限制类型和大小**（只收 jpg/png、不超过几 MB），否则别人能往你服务器里塞垃圾文件

## 二、上线前建议做（不做也能上，但迟早被打）

### 安全（最该补的一块）

| 现在的情况 | 上线前应该 |
|---|---|
| `@CrossOrigin(origins = "*")`：谁都能跨域调你的接口 | 改成只允许你自己的前端域名 |
| 登录**没有次数限制** | 同一 IP 每分钟最多几次，防止别人暴力猜密码 |
| 令牌存在**内存**里，后端一重启就掉线 | 令牌落库（可参考 Cyber-Tunnel 的 `login_token` 表），还能"踢设备下线" |
| 站长密码只要够长 | 至少 12 位、别和别处重复 |
| 服务器通常用 root + 密码登录 | 改成只允许 SSH 密钥登录，再装个 fail2ban |
| 端口默认可能都开着 | 安全组只开 22 / 80 / 443 |

### 数据库

- 确认字符集是 `utf8mb4`（emoji 才存得住 —— 我们测过 😀 是可以的）
- 给 `essay.date_at`、`post.published_at` 加索引（数据多了分页才快）
- **上线后把 `ddl-auto=update` 改成 `validate`**：别让程序自己改表结构了
- 以后再改表结构，用"迁移脚本"（Flyway / Liquibase）：有版本、能回滚

### 体验

- 图片懒加载 + 再压一压（现在背景图 200KB、头像 60KB，还能接受）
- `index.html` 现在 28KB，所有页面都挤在一个文件里 —— 内容多了要拆开
- 分享出去的样子：`og:title` / `og:image` / `sitemap.xml` / `robots.txt`
- 手机上完整走一遍（现在只有 760px 一个断点）
- 无障碍：键盘能不能操作完、对比度够不够（刚修过一轮）

### 工程

- GitHub Actions：push 到 main 自动部署前端（现在靠 Pages 自己构建）
- 后端也上 CI：至少跑一次 `.\mvnw.cmd test`（现在只有一个自动生成的空测试）
- 大改动开 `dev` 分支，别直接推 main
- 监控：定时访问 `/api/hello`，挂了给你发通知
- 加一份 `LICENSE`（不然别人不知道能不能用你的代码）

## 三、AI 分身（单独列，因为它是"产品"，不只是"功能"）

- **素材**：把随笔 / 技能 / 项目 / 兴趣爱好整理成一段段"知识片段"
- **检索**：简单版 = 关键词匹配；升级版 = 向量检索（RAG：先找出最相关的几段，再让模型照着答）
- **密钥**：只放后端（环境变量）—— 前端**永远拿不到**
- **成本控制**：限制回答长度、每人每天限次数、常见问题缓存
- **体验**：流式输出（一个字一个字蹦出来）、一开口就说"我是分身，可能说错"
- **兜底**：模型不可用或超预算时，给一句人话，别白屏

## 五、推荐的"最小上线"顺序

先让别人能用，再慢慢升级：

1. **前端读接口 + 登录** —— 写完在本地就能给同学看（后端还在你电脑上）
2. **后端上云 + 域名 + HTTPS** —— 到这一步才算"真的有网站了"
3. **管理页发帖 / 改资料 / 传图** —— 让它真的好用
4. **AI 分身** —— 最亮的部分放最后慢慢打磨，也是面试最好聊的话题
5. **加固**：令牌落库 / 登录限流 / 自动备份 / 监控

## 六、一句话总结

```
写死的页面 → 从数据库读 → 部署到服务器 → 域名 + HTTPS → 访客看到
                        ↑ 这四步是一个整体，缺一步别人就看不到
AI 分身是这条链路「上面」的一层，所以它得等前面稳了再上。
```
