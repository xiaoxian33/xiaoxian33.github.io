# 🚀 上线手册（省钱版：国内轻量 + 备案）

> 面向小白，一步一条命令。**每一节都写了三件事**：
> ① 你做什么 ② 应该看到什么 ③ 出错了怎么办
>
> 分工：**第 3 步之后我全程代打**，你只管粘贴命令、把输出发给我。
> 总时间：买 + 装 ≈ **2~3 小时**；备案**等 1~2 周**（这段时间不耽误你继续用现在的网站）。

## 总览：我们要把东西搬到哪

    现在：
      你的浏览器 → GitHub Pages（前端） → 你电脑 :8080（后端） → 你电脑 :3306（MySQL）

    上线后：
      你的浏览器 → 你的域名 → 服务器 :443（Nginx） → 服务器 :8080（后端） → 服务器 :3306（MySQL）
                                  └─ 顺便也提供前端静态文件（前后端同一台 = 同源，省掉跨域和混合内容）

## 第 0 步 · 买之前的最后检查

| 检查 | 要求 |
|---|---|
| 内存 | **≥ 2GB**（能买到 4核4G 的 109 元档最好） |
| 系统 | **Ubuntu 24.04 LTS**（不要 Windows） |
| 时长 | **买 1 年**（备案要求 ≥3 个月；首年优惠也只有一次） |
| 地域 | 离你近的国内机房（上海 / 广州 / 南京） |
| 带宽 / 存储 | ≥ 3Mbps，≥ 40GB（套餐自带，不用加钱） |
| 手边要有 | 手机（备案要短信/人脸核验）、身份证 |

## 第 1 步 · 买服务器

1. 搜「**腾讯云 轻量应用服务器 活动**」→ 进活动页
2. 在**新用户专享**里找那一档：**4核4G3M，首年 109 元**（活动写到 2026-12-30，实际以下单页为准）
3. 地域：选**上海 / 广州 / 南京**（离你近的）
4. 镜像：**系统镜像 → Ubuntu → 24.04 LTS**（不要选"应用镜像"里的 WordPress 之类）
5. 时长：**1 年**
6. 付款：支付宝 / 微信都行
7. 买完做两件事：
   - 控制台 → 实例 → 记下**公网 IP**（形如 `123.45.67.89`）
   - **重置一次实例密码**（Linux 实例默认没有密码，必须重置才能用密码登录）

**应该看到**：实例状态是"运行中"，有一个公网 IP，并且已经重置了密码。

⚠️ **顺手确认防火墙**：轻量的"防火墙"默认放行 **22 / 80 / 443**。
现在只需要确认 **22** 是通的（否则第 3 步连不上）。8080 **不要**对外放行（后端只让 Nginx 从本机访问）。

## 第 2 步 · 买域名 + 实名 + 提交备案（提交完就往下走，别干等）

**顺序很重要，错了会白等：**

1. 在**同一家**（腾讯云）买域名 —— 备案要求域名注册商是国内服务商
2. **立刻做域名实名认证**（不实名会被 `Serverhold` = 暂停解析，网站打不开）
3. 等实名通过（几小时 ~ 1 天）
4. 在腾讯云 App / 控制台提交**备案**（入口叫「网站备案」）
5. 提交完就开始等 —— **继续做第 3~10 步，不要干等**

| 备案要点 | 说明 |
|---|---|
| 购买时长要求 | 腾讯云原话：**仅支持购买时长 ≥3 个月的国内实例**备案（所以我们买 1 年） |
| 要准备 | 身份证、本人手机、邮箱、网站名称、网站内容说明 |
| 耗时 | 服务商初审 1~2 天 + 管局审核 5~20 天（一般 **1~2 周**） |
| 个人备案注意 | 非经营性个人网站可以（博客/作品集）；网站名称别含地名、国名、敏感词 |
| **备案期间能不能访问** | 域名**先不要**解析到国内服务器（未备案会被拦）。可以先用 `http://公网IP:8080` 测后端（非 80/443 端口一般不被拦） |
| 价格 | 组合购域名可低至 **1 元首年**；平时 .com 首年 ¥30~60，**续费 ¥70~90/年** |

## 第 3 步 · 连上服务器（SSH）

Windows 自带的 `ssh` 就能用（在这个 VS Code 的终端或 PowerShell 里直接敲）：

```bash
ssh root@你的公网IP
```

- 第一次会问 `Are you sure you want to continue connecting?` → 输入 **`yes`** 回车
- 然后输入第 1 步重置的密码
  ⚠️ **输密码时屏幕上什么都不显示**（不显示圆点也不显示星号），这是正常的，敲完直接回车
- 看到类似 `root@VM-8-4-ubuntu:~#` 的提示符 = 成功连上了 ✅

**出错了怎么办**

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `Connection refused` | 22 端口没放行 | 控制台 → 防火墙 → 放行 22 |
| `Connection timed out` | IP 写错 / 被防火墙拦 | 核对公网 IP，确认实例是"运行中" |
| `Permission denied` | 密码不对或用户名不对 | 控制台重置密码，等 1 分钟再试；用户名试 `ubuntu` |
| 提示 host key 变了 | 你重装过系统 | 删掉旧记录：`ssh-keygen -R 你的IP` |

> ✅ **到这里为止是"你操作 + 我指导"。从第 4 步开始，我把每条命令都写全，你粘贴即可。**

## 第 4 步 · 装环境（JDK 21 + MySQL 8）

> 在 SSH 里逐段粘贴。第一次装东西要 2~5 分钟，正常。

```bash
# 4.1 更新软件源（第一次会慢一点）
sudo apt update && sudo apt upgrade -y

# 4.2 装 JDK 21（我们的 jar 是用 21 编译的）
sudo apt install -y openjdk-21-jdk
java -version          # 应该看到 openjdk version "21.x.x"

# 4.3 装 MySQL 8
sudo apt install -y mysql-server
sudo systemctl enable --now mysql
systemctl status mysql --no-pager    # 看到 active (running) 就对了
```

**4.4 建数据库 + 建专用账号**（应用不要用 root 连数据库）

```bash
sudo mysql
```

进入 MySQL 提示符后，**逐行**粘贴（把密码换成你自己的）：

```sql
CREATE DATABASE site_db CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'site'@'localhost' IDENTIFIED BY '在这里换成你的强密码';
GRANT ALL PRIVILEGES ON site_db.* TO 'site'@'localhost';
FLUSH PRIVILEGES;
EXIT;
```

**验证**：

```bash
mysql -u site -p site_db -e "SELECT 1;"
```

**应该看到**：输入你刚设的密码后，打印出一行 `1`。✅

**三个要点（很重要）**

| 要点 | 为什么 |
|---|---|
| `utf8mb4` 必须写 | 不写中文会变"锟斤拷" |
| 用专用账号 `site`，不用 root | root 权限太大，应用被攻破时损失最小化 |
| MySQL 的 `bind-address` 保持默认 `127.0.0.1` | 只允许本机连接 —— **这是好事，别改** |

## 第 6 步 · 上传到服务器

### 6.1 在服务器上建目录 + 建一个专用账号（SSH 里粘）

```bash
sudo mkdir -p /opt/site/uploads /var/www/site
sudo useradd -r -s /usr/sbin/nologin -d /opt/site site || true
sudo chown -R site:site /opt/site
```

### 6.2 从你的 Windows 上传（**新开一个 PowerShell 窗口**，不是在 SSH 里）

```powershell
$ip = "你的公网IP"
scp "D:\Java works\xiaoxian33.github.io\server\target\site-server-0.0.1-SNAPSHOT.jar" root@${ip}:/opt/site/app.jar
scp "$env:USERPROFILE\Desktop\site_db.sql" root@${ip}:/opt/site/
```

图片（有就传，没有就跳过）：

```powershell
scp -r "D:\Java works\xiaoxian33.github.io\server\uploads\*" root@${ip}:/opt/site/uploads/
```

前端静态文件：

```powershell
scp "D:\Java works\xiaoxian33.github.io\index.html" root@${ip}:/var/www/site/
scp -r "D:\Java works\xiaoxian33.github.io\assets" root@${ip}:/var/www/site/
```

> ⚠️ 路径里有空格（`Java works`），**引号一个都不能省**。每条都会让你输一次密码。

### 6.3 导入数据库（回 SSH 里）

```bash
sudo mysql < /opt/site/site_db.sql          # 把数据灌进去
rm -f /opt/site/site_db.sql                 # 导入完就删（里面有你的内容）
sudo mysql -e "SELECT COUNT(*) FROM site_db.essay;"    # 应该看到 8
```

### 6.4 写启动脚本 `/opt/site/run.sh`

```bash
sudo tee /opt/site/run.sh > /dev/null <<'EOF'
#!/bin/bash
export SPRING_DATASOURCE_URL='jdbc:mysql://127.0.0.1:3306/site_db?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai'
export SPRING_DATASOURCE_USERNAME='site'
export SPRING_DATASOURCE_PASSWORD='改成你的数据库密码'
export APP_OWNER_PASSWORD='改成你的新站长密码'
export APP_UPLOAD_DIR='/opt/site/uploads'
export SPRING_JPA_HIBERNATE_DDL_AUTO='validate'
export SPRING_JPA_SHOW_SQL='false'
exec java -Xmx512m -jar /opt/site/app.jar
EOF

sudo chmod +x /opt/site/run.sh
sudo chmod 600 /opt/site/run.sh        # 里面有密码，只让 root 读
sudo chown site:site /opt/site/run.sh
sudo chown -R site:site /opt/site
```

> `-Xmx512m`：给 JVM 一个内存上限。2GB 的机器上很关键，别让它敞开了吃。

## 第 7 步 · 先手动跑一次（验证）

```bash
sudo -u site /opt/site/run.sh
```

**应该看到**（等 5~10 秒）：

```
Started SiteServerApplication in x.xxx seconds
Tomcat started on port 8080
```

⚠️ 这个 SSH 窗口现在被程序占住了（这就是"前台运行"）。**另开一个 SSH 窗口**做验证：

```bash
curl -s http://127.0.0.1:8080/api/hello                    # 应该返回一段 JSON
curl -s http://127.0.0.1:8080/api/essays | head -c 200     # 应该看到你的随笔内容
curl -s http://127.0.0.1:8080/api/posts                    # 帖子列表
```

**验证通过后**：回到第一个窗口按 `Ctrl + C` 停掉它（下一步交给 systemd 来守护）。

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `Connection refused` 连不上数据库 | 账号/密码不对 或 MySQL 没起 | `systemctl status mysql`；核对 4.4 的密码 |
| `Unable to determine Dialect...` | 连不上数据库的连带症状 | 同上（**这次彩排踩过的就是它**） |
| 启动很慢 / 卡住 | 内存不够（1GB 机器） | 确认买的是 ≥2GB；或给 JVM 调小 `-Xmx` |
| 端口被占用 | 上一次没停干净 | `sudo pkill -f app.jar` 再重来 |

> ✅ 走到这里，你的后端已经在**服务器上**跑起来了 —— 这已经是最难的一步。
> 接下来只是"让它更省心"（守护、Nginx、HTTPS）。

## 第 8 步 · 交给 systemd 守护（开机自启 / 崩了自动拉起）

```bash
sudo tee /etc/systemd/system/site-server.service > /dev/null <<'EOF'
[Unit]
Description=xiaoxian33 个人站后端
# ★ 我们彩排时踩过"MySQL 没起、后端直接死"——这两行就是解药
After=network-online.target mysql.service
Wants=network-online.target

[Service]
User=site
WorkingDirectory=/opt/site
ExecStart=/opt/site/run.sh
SuccessExitStatus=143
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now site-server
systemctl status site-server --no-pager        # 看到 active (running)
```

**验证三件事**

```bash
curl -s http://127.0.0.1:8080/api/hello              # 后端在跑
sudo systemctl restart site-server                   # 重启也不怕
journalctl -u site-server -n 30 --no-pager           # 看日志（跟 Windows 下的控制台一样）
sudo reboot                                          # 可选：重启整台机器，等 1 分钟
```

> ⚠️ 一条已知隐患：如果**开机时 MySQL 还没就绪**，后端会失败一次，
> 但 `Restart=on-failure` 会在 10 秒后重试 —— 那时候数据库已经起来了，于是成功。
> **这就是"自动重试"兜住"启动顺序"的经典做法。**

## 第 9 步 · Nginx：反代接口 + 顺便提供前端

```bash
sudo apt install -y nginx
sudo tee /etc/nginx/sites-available/site > /dev/null <<'EOF'
server {
    listen 80;
    server_name _;                       # 域名备案下来后再改成你的域名

    # ① 前端静态文件（index.html + assets/）
    root /var/www/site;
    index index.html;
    location / {
        try_files $uri $uri/ =404;
    }

    # ② 图片：让 Nginx 直接从磁盘读（比走后端快，也不占 Java 的性能）
    location /uploads/ {
        alias /opt/site/uploads/;
        expires 30d;
    }

    # ③ 接口：转给后面的 Spring Boot
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # ④ ★ 不写这行，上传超过 1MB 的图会被 Nginx 直接拒掉（默认只给 1MB）
    client_max_body_size 30m;
}
EOF

sudo ln -sf /etc/nginx/sites-available/site /etc/nginx/sites-enabled/site
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t                    # 应该看到 syntax is ok / test is successful
sudo systemctl reload nginx
```

**验证**

```bash
curl -s http://127.0.0.1/ | head -c 200            # 应返回你的首页 HTML
curl -s http://127.0.0.1/api/hello                 # 应返回 JSON（说明反代通了）
```

**前端还要改一处（我来改，你审）**：
`assets/js/app.js` 里的 `API_BASE = 'http://localhost:8080'` → 改成 **`''`（空字符串 = 同源）**。
因为现在前端和后端是**同一个域名**，请求直接写 `/api/...` 就行 —— **跨域、混合内容这两个坑从此不存在**。改完记得把 `index.html` 里的 `?v=` 版本号 +1。

## 第 10 步 · HTTPS 证书（⚠️ 要等备案通过 + 域名解析做完）

> 为什么必须等：`certbot` 要能通过 `http://你的域名` 验证到你 ——
> 而**没备案的域名解析到国内服务器是打不通的**。所以顺序是：备案过 → 切解析（第 11 步）→ 再回来做这一步。

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d 你的域名 -d www.你的域名
```

- 要你填邮箱（续期通知用）→ 同意条款 → 问要不要自动跳转 https → **选 2（Redirect）**
- 完成后再验证一次：

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://你的域名/       # 应返回 200
sudo systemctl list-timers | grep certbot                        # 自动续期已就位
```

**这一节之后，你的网站就是真正的 https 全站了。** ✅

## 第 11 步 · 备案通过 → 切解析 → 验收

备案通过后（腾讯云会发短信/站内信，给你一个**备案号**）：

1. 控制台 → **云解析 DNS**（在你的域名下面）
2. 添加记录：

| 主机记录 | 类型 | 记录值 |
|---|---|---|
| `@` | A | 你的服务器公网 IP |
| `www` | A | 你的服务器公网 IP |

3. 等 5~30 分钟生效，验证：

```bash
nslookup 你的域名          # 在 Windows 的 PowerShell 里敲
ping 你的域名
```

4. 回到第 10 步做 HTTPS 证书。

### 验收清单（用电脑 + 用手机**流量**各走一遍）

- [ ] `https://你的域名` 打开是首页
- [ ] 页脚显示「后端已连接」
- [ ] ↑ + ← 输入**新站长密码**能进编辑模式
- [ ] 发一条带图的帖子 → 图片正常显示
- [ ] 刷新页面 → 内容还在（说明真的写进服务器数据库了）
- [ ] 手机上打开 → 图片也能看

### 顺便处理 GitHub Pages

现在有两份前端了，**建议只留服务器这份**（Pages 那份的 `API_BASE` 还指着 localhost，访客看到的是"没数据"）：

| 选项 | 做法 |
|---|---|
| **A（推荐）** | 仓库留着当代码仓库，**把 Pages 站点关掉**（Settings → Pages → 取消发布） |
| B | 让 Pages 继续跑：把它的 `API_BASE` 指向 `https://你的域名`，并且后端 CORS 要放行 `https://xiaoxian33.github.io` |

## 第 12 步 · 备份 + 收尾加固

### 12.1 备份脚本（数据库 + 图片一起备）

```bash
sudo tee /opt/site/backup.sh > /dev/null <<'EOF'
#!/bin/bash
set -e
D=/opt/site/backups/$(date +%F)
mkdir -p "$D"
mysqldump -u root site_db > "$D/site_db.sql"          # 数据
tar czf "$D/uploads.tar.gz" -C /opt/site uploads      # 图片（数据库里只有路径！）
find /opt/site/backups -maxdepth 1 -type d -mtime +14 -exec rm -rf {} +   # 只留最近 14 天
echo "backup done: $D"
EOF
sudo chmod +x /opt/site/backup.sh
sudo /opt/site/backup.sh            # 先手动跑一次，确认能出文件
sudo crontab -l | { cat; echo "30 4 * * * /opt/site/backup.sh"; } | sudo crontab -
sudo crontab -l                     # 确认定时任务写进去了
```

> ⚠️ **只备份数据库是不够的**：图片文件不在数据库里，`mysqldump` 备不到它们 —— 所以脚本里两样都备。

### 12.2 收尾清单

- [ ] 站长密码已换成强密码（`/opt/site/run.sh` 里那个）
- [ ] `ddl-auto=validate`、`show-sql=false` 已生效（都在 run.sh 里）
- [ ] **8080 没有对公网放行**（只有 22 / 80 / 443）
- [ ] 数据库只允许本机连（MySQL 默认就是这样，别改）
- [ ] CORS 收紧：把 10 个 `@CrossOrigin(origins = "*")` 改成你的域名（同源部署后风险已很小，但更干净）
- [ ] 备份任务跑通过一次
- [ ] 把这几样记在你能找到的地方：**服务器 IP / root 密码 / 数据库密码 / 站长密码**

## 附录 B · 故障排查总表

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| 网站打不开（域名） | 备案没过 / 解析没生效 / 证书没签 | `nslookup` 查解析；`sudo nginx -t`；看第 10 步 |
| 页面能开，"后端未连接" | 后端挂了 / Nginx 反代没配好 | `systemctl status site-server`；`journalctl -u site-server -n 50` |

## 附录 C · 这次准备阶段已经踩过的坑（别再踩）

1. **启动顺序**：MySQL 没起 → 后端直接死，报 `Unable to determine Dialect...`
   → 解药：systemd 里 `After=mysql.service` + `Restart=on-failure`（第 8 步已内置）
2. **jar 里带着密码**：`application-local.properties` 被打进包里（我拆开看过）
   → 解药：服务器上用**环境变量**覆盖（第 6.4 步的 run.sh）；这个 jar **不要发给别人**
3. **先导入数据再启动后端**：空了的话 `DataSeeder` 会往数据库塞 8 篇旧文和一份资料
   → 手册的顺序（第 6.3 先导入 → 第 7 步才启动）已经避开
